# 她的世界 · HER WORLD

一个面向**电脑浏览器**的互动叙事序章。一个被搁置、尚未完成的程序被你唤醒；你们一起认识雨、修改天气，为第一场雨命名，并在运行日志中发现被留下的记忆。

- 初次相遇约 5–10 分钟；可以停留、换话题与继续聊天，不按消息数量推进
- 结局：这里只是第一次相遇，之后的故事与最终结局尚未确定
- 原创 HTML / CSS / JavaScript / Canvas，无运行时依赖，无第三方资源、追踪器或分析服务
- 使用真实 DOM 交互与纯字符绘制的单色雨夜场景，不是把设计图铺成页面

## 当前版本

界面会显示 `PROLOGUE v0.3.5`，样式与脚本使用一致的版本化路径，便于确认更新。

## 开始

用本地 HTTP 服务打开此目录，或发布至 GitHub Pages 的仓库根目录。无需构建步骤。

```sh
python3 -m http.server 8765
```

打开 `http://localhost:8765`，点击「建立连接」。可选择自己的 DMXAPI Key，或明确选择离线试玩。

## AI 与离线模式

AI 模式由玩家本人在密码框中输入并提交 Key。浏览器直接向以下固定地址发送请求：

- API：`https://www.dmxapi.cn/v1/chat/completions`
- 模型：`glm-5.3-flash`
- 每次开场或回应一次请求；无自动重试
- `max_tokens: 2048`（含推理），`reasoning_effort: low`；等待上限 30 秒；响应体上限 64 KiB
- 接受最终普通文本、文本内容块与兼容 JSON 对白，隐藏推理内容；模型只能提出当前已开放的天气/故事能力，并给出本条输入中的原文证据；本地再次校验后才提交，不能任意改状态或结局
- 本页每次连接最多 20 次请求，仅为使用提醒，**不是计费保障或防滥用安全边界**

如果请求、额度或回复解析出错，故事停在当前选择，显示明确错误。已知 HTTP 状态不会被可选的响应清理失败覆盖；浏览器未提供可读响应时，不猜测状态码或断言 Key 有误。粘贴完整请求头、Bearer 前缀或带引号的内容会被本地校验提示，而不是悄悄改写凭据。玩家可以手动重试，或明确切换到作者编写的离线文本。不会把离线文本冒充 AI 回应。

**自动化测试全部使用模拟请求。用户亲自在云浏览器输入并连接后，进行过一次限定的真实对话检查：5 次请求（包含 1 次手动重试），发现混合对白/JSON 显示和自然语言能力授权问题，随后停止请求进行修正。没有读取、复制、保存或代填真实 Key。随后 v0.3.2 在玩家亲自重新连接后完成了 15 次真实自由对话：全程不用剧情/天气选项按钮，达到全部 9 个片刻并验证告别后重开、名字回忆与匿名选择。没有错误、重试或协议泄漏。云浏览器结果不代表所有网络环境。** 如果服务商不允许浏览器直连，静态页面无法解除这个限制，需要另行部署安全转发服务。

### Key 与隐私

- Key 仅保存在当前页面 JavaScript 闭包内存中，提交后立即清空输入框
- Key 不写入 localStorage、sessionStorage、IndexedDB、Cookie、网址、日志或存档
- 刷新、离开页面、断开连接与重新开始会清除 Key；恢复进度后须重新输入
- 请求禁止重定向，不携带 Cookie 或 Referrer，使用 `cache: no-store`
- 浏览器扩展和页面脚本仍可读取运行时信息；建议使用低额度专用 Key，并在服务商设置额度
- 近期对话与当前回应会发送给 DMXAPI；游戏选择和 AI 文本会保存在本地浏览器
- 角色的“记忆”是虚构叙事；角色选择不保存某条引用，不等于删除完整本机存档

不要把真实 Key 写入源码、测试、提交记录或聊天。仓库没有服务器，也不包含 Key。

## 操作

- 随时自由输入最多 80 个字，选项是提示；通过“把雨叫做夜航”命名，名字最多 20 个字
- 输入框上方保留一条当前可以一起做的事：描述雨、画出雨、改变雨、命名、查看记录、讨论保留理由和来访者记忆，再到暂别。可以直接用自己的话回应，也可以先聊别的
- 邀请与已确认状态一致；她完整说完后才更新。岔开话题不会完成邀请，也不会每轮把同一句问题插回对话
- 创建第一场雨、雨量、暂停与恢复都可由对话触发；停雨后保留选好的密度
- 右侧天气提示只会把一句话填入输入框，不自动发送或执行
- 话题与天气相互独立，聊天不会自动推进。问时间、回忆或假设不会被当作描述雨或修改指令
- 预设问题要得到相关回答才算完成；也可以先换话题，之后再回来
- 「运行日志」由玩家主动打开；第一场雨画出、命名后，阅读符合条件的日志才发现记忆
- 「记忆」查看留下的记录；告别只是暂别，仍可继续输入
- “conversation focus” 仅从已显示的对话和世界事实计算：按轮次衰减、归一化显示，不是模型的真实注意力
- AI 开场显示模型给出的完整开场，不再叠加第二套固定台词；离线开场仍使用作者文本
- 她的对白逐条、逐字出现，标点处稍停；按空格或「显示本句」完成当前句
- 对白展示期间暂时锁定输入；完成的故事状态先保存，刷新恢复完整记录，不重复收费
- 日志逐行出现，记忆和世界变化在对应对白后逐渐呈现
- 页眉暂停按钮控制动态效果；遵循系统减少动态效果设置并立即显示完整文本
- 底部连接状态按钮可更换模式或断开
- 「重新开始」需要确认；普通刷新恢复进度，不保留 Key
- 支持键盘选择、可见焦点、选项后焦点移动、日志 Tab 键盘左右切换

## 非线性状态与边界

状态版本为 v3，由有限的对话/日志事件重建。天气操作采用精确类型与允许列表；问题回答和天气请求分别判断。错误、取消与迟到回应不会提交事件。普通模型散文可用于聊天，但不能独自执行天气修改；明确操作未被模型按协议选中时，会显示“没有执行天气修改”，保持原状。

在线时，模型可以理解自由表达的天气愿望、换话题、命名、保留理由、来访者记忆选择与告别。它只能选择本地当前允许的能力，必须提供本条输入中的原文证据；名字还须逐字出现在当前输入，记住来访者需要明确同意。否定、假设、引用与回忆不会被当成当前执行请求，但“不用记我”会被识别为明确的匿名选择。学习雨与实际创建雨仍是两个独立事件。日志发现需要玩家实际打开并看见记录，界面会给出邀请。

这些判定作为事件保存，刷新时不重新调用模型。离线模式支持保守的预设识别，不是通用语言理解；未确定的意思保持原状态。每条消息最多执行一项天气操作；命名与一项天气操作可以同时发生。每局最多 200 条事件，不自动丢弃旧记录；达到上限后需要重新开始。v2 的有效存档会保留完整旧对话、名字、天气和记忆，迁移为可继续聊天的状态；迁移时旧存档键保持不动；确认“重新开始”时会清除这份旧副本。

可选邀请是独立、受校验的会话状态，不以模型随口提到某个问题为依据。模型收到同一条邀请及当前世界事实；只有实际已发出的雨描述问题可以开放相关回答判定。旧存档恢复时在原事件之后建立新的邀请边界，不重新解释过去的消息。邀请本身不创建天气、命名或取得记忆同意。

请求还携带一份很小的来源记录：首次被确认的雨描述、最近一次正式命名的玩家原话，以及当前来访者记忆选择。它们从已验证事件生成，不依赖最近六条对白；未知的旧来源保持为空。模型被要求据此回忆，不编造“你曾经说过”的内容，也不能把匿名选择说成同意留下来访者引用。

## 视觉边界

右侧世界仅用单一中性灰白色字符与黑底构成，明暗通过字符密度和透明度变化。对话、按钮、边框保持原来的青灰、象牙白与暖色 UI。RGB 输入或通过上传图片认识颜色，是未来章节方向，当前 demo 不提供上传或颜色教学。
