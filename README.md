# 她的世界 · HER WORLD

一个面向**电脑浏览器**的互动叙事序章。一个被搁置、尚未完成的程序被你唤醒；你们一起认识雨、修改天气，为第一场雨命名，并在运行日志中发现被留下的记忆。也可以暂时离开主线，用对话把新物件放进字符世界，再修改它们的样子和意义。

- 初次相遇约 5–10 分钟；可以停留、换话题与继续聊天，不按消息数量推进
- 结局：这里只是第一次相遇，之后的故事与最终结局尚未确定
- 原创 HTML / CSS / JavaScript / Canvas，无运行时依赖，无第三方资源、追踪器或分析服务
- 使用真实 DOM 交互与纯字符绘制的单色雨夜场景，不是把设计图铺成页面

## 当前版本

界面会显示 `PROLOGUE v0.5.1`，样式与脚本使用一致的版本化路径，便于确认更新。

## 开始

用本地 HTTP 服务打开此目录，或发布至 GitHub Pages 的仓库根目录。无需构建步骤。

```sh
python3 -m http.server 8765
```

打开 `http://localhost:8765`，点击「建立连接」。可亲自输入专用转发访问密码，或明确选择离线试玩。

## AI 与离线模式

AI 模式由玩家本人在密码框中输入并提交专用转发访问密码。浏览器向以下固定代理地址发送请求；对话和世界状态由该服务器转发给 DMXAPI。上游 DMXAPI Key 由服务器管理，浏览器不接收它：

- API：`https://216.235.248.104/v1/chat/completions`
- 模型：`glm-5.3-flash`
- 每次开场或回应一次请求；无自动重试
- `max_tokens: 2048`（含推理），`reasoning_effort: low`；等待上限 30 秒；请求体上限 128 KiB，响应体上限 64 KiB
- 开场可接受最终普通文本；之后使用一个完整的结构化回合，统一给出对白、天气、物件、记忆笔记、叙事日志与故事意图。模型理解自然语言，本地只执行通过类型、容量、状态前提和明确同意校验的操作；不读取或显示推理内容
- 本页每次连接最多 20 次请求，仅为使用提醒，**不是计费保障或防滥用安全边界**

如果请求、额度或回复解析出错，故事停在当前选择，显示明确错误。已知 HTTP 状态不会被可选的响应清理失败覆盖；浏览器未提供可读响应时，不猜测状态码或断言访问密码有误。粘贴完整请求头、Bearer 前缀或带引号的内容会被本地校验提示，而不是悄悄改写凭据。玩家可以手动重试，或明确切换到作者编写的离线文本。不会把离线文本冒充 AI 回应。

**自动化测试全部使用模拟请求。用户亲自在云浏览器输入并连接后，进行过一次限定的真实对话检查：5 次请求（包含 1 次手动重试），发现混合对白/JSON 显示和自然语言能力授权问题，随后停止请求进行修正。没有读取、复制、保存或代填真实 Key。随后 v0.3.2 在玩家亲自重新连接后完成了 15 次真实自由对话：全程不用剧情/天气选项按钮，达到全部 9 个片刻并验证告别后重开、名字回忆与匿名选择。没有错误、重试或协议泄漏。云浏览器结果不代表所有网络环境。** 以上为历史直连版本的结果；v0.5.1 使用专用 HTTPS 转发，真实模型体验仍需单独验证。

### 访问密码与隐私

- 访问密码仅保存在当前页面 JavaScript 闭包内存中，提交后立即清空输入框
- 密码只作为 Bearer 认证发往固定的 `216.235.248.104` HTTPS 转发服务，不放入模型消息
- 密码不写入 localStorage、sessionStorage、IndexedDB、Cookie、网址、日志或存档
- 刷新、离开页面、断开与重新开始会清除密码；恢复进度后须由玩家重新输入
- 请求禁止重定向，不携带 Cookie 或 Referrer，使用 `cache: no-store`
- 浏览器扩展和页面脚本仍可读取运行时信息；服务端配额和访问控制仍由转发服务管理
- 近期对话、已保存的来源与当前世界状态会经过该 VPS 发给 DMXAPI；游戏选择和 AI 文本保存在本地浏览器
- 角色选择不保留某条引用，不等于删除完整本机对话记录

不要把访问密码或上游 Key 写入源码、测试、提交记录或聊天。这个静态仓库不包含服务器凭据；转发服务器另行部署。

## 操作

- 随时自由输入最多 80 个字，选项是提示；通过“把雨叫做夜航”命名，名字最多 20 个字
- 输入框上方保留一条当前可以一起做的事：描述雨、画出雨、改变雨、命名、查看记录、讨论保留理由和来访者记忆，再到暂别。可以直接用自己的话回应，也可以先聊别的
- 邀请与已确认状态一致；对应变化随确认句更新，下一次输入在对白结束后开放。岔开话题不应完成邀请，也不应每轮把同一句问题插回对话
- 创建第一场雨、雨量、暂停与恢复都可由对话触发；停雨后保留选好的密度
- 右侧天气提示只会把一句话填入输入框，不自动发送或执行
- 话题与天气相互独立，聊天不会自动推进。问时间、回忆或假设不会被当作描述雨或修改指令
- 预设问题要得到相关回答才算完成；也可以先换话题，之后再回来
- 「运行日志」可以由玩家点击打开，也可以用对话请她打开；第一场雨画出、命名后，实际显示符合条件的记录才发现记忆
- 「记忆」查看留下的记录；告别只是暂别，仍可继续输入
- “conversation focus” 仅从已显示的对话和世界事实计算：按轮次衰减、归一化显示，不是模型的真实注意力
- AI 开场显示模型给出的完整开场，不再叠加第二套固定台词；离线开场仍使用作者文本
- 她的对白逐条、逐字出现，标点处稍停；按空格或「显示本句」完成当前句
- 对白展示期间暂时锁定输入；完成的故事状态先保存，刷新恢复完整记录，不重复收费
- 新日志逐行出现，已存在的日志立即显示；世界、记忆和日志在模型指定的确认句结束时一起更新，不再等最后一句才出现
- 页眉暂停按钮控制动态效果；遵循系统减少动态效果设置并立即显示完整文本
- 「世界」查看共同添上的物件、位置、字符外观、意义与来源；其中的提示只填入聊天，不直接修改世界
- 底部连接状态按钮可更换模式或断开
- 「重新开始」需要确认；普通刷新恢复进度，不保留访问密码
- 支持键盘选择、可见焦点、选项后焦点移动、日志 Tab 键盘左右切换

## 非线性状态与边界

状态版本仍为 v3，以新增的带类型回合事件保存。一个在线回应同时包含对白、天气操作、故事意图、物件修改、记忆笔记、叙事日志与可选面板请求。整个回合通过校验后才保存；任何无效目标、越界图案、未知字段或不满足主线前提的操作都会使整轮失败，不展示“已经完成”的对白，也不留下半次修改。取消或迟到响应不会提交。

在线模型负责理解自由表达、明确请求、假设、回忆、指代和相关回答。除了“允许她记住来访者”必须保留本轮明确同意证据，普通操作不再要求命中本地词表或把名字、意义逐字摘自玩家输入。模型收到当前事实、待回答的邀请、原始来源与近期对话；可主动邀请下一步，但不得因为聊天轮数或无关回答自动推进。这样的开放理解依赖模型判断，类型校验不能保证每次语义理解都正确。

本地保留九个主线片刻及必要前提，模型不能创建任意剧情字段或跳过实际日志发现。学习雨和画出雨是不同能力；玩家一轮同时描述并请求绘制时可以一起发生。物件编辑和世界笔记不推进主线。告别仍可继续聊天。离线模式保留保守的本地识别与作者对白，并明确说明理解范围。

每轮最多一项天气操作、三项物件操作、三项笔记修改和三条叙事日志；最多十二条可修改笔记、八件物体和二百条事件。对白最多三句。新增或修改的世界笔记显示为“她的笔记”，保留最初及最近对应的玩家原话，与固定主线记忆、玩家赋予的意义和她的理解分开。清除当前笔记或注解不会重写原始对话。

这些结果作为完整事件保存，刷新不重新调用模型。可见世界按确认句同步揭示；即使刷新发生在逐字展示中，也恢复已提交的完整回合。旧 v2/v3 存档按原有规则重放，不重新用模型解释过去；确认重新开始只清除本游戏进度，不动其他存储。

请求还携带一份很小的来源记录：首次被确认的雨描述、最近一次正式命名的玩家原话，以及当前来访者记忆选择。它们从已验证事件生成，不依赖最近六条对白；未知的旧来源保持为空。模型被要求据此回忆，不编造“你曾经说过”的内容，也不能把匿名选择说成同意留下来访者引用。

## 一起修改字符世界

主线仍保留，物件操作是独立的一层。可以说“在窗边放一张能坐两个人的长椅”“把长椅移到左边”“把长椅放大一点”，也可以要求新的外观。AI 根据描述生成新的普通 ASCII 图案，而不是从几个固定精灵中选一个。物件标签可以自然概括玩家的描述，最多 40 个字；新图案可以自由生成，原始输入另存为来源。浏览器保存字符、位置和尺寸，本地逐帧绘制；动画不会额外调用模型。

当前边界：100×60 逻辑格，同时最多 8 件物体；每件字符图案最多 24 列、10 行，大小为 1–3 倍，必须完整落在画面内；一轮最多 3 项修改。生成的图案只是文字数据，不执行 JavaScript、HTML、SVG、网址或代码。整批修改通过校验后才提交，失败、取消或断开不留下半次操作。

「你赋予的意义」与「她目前的理解」是两份可单独修改的注解。例如“长椅对我代表一起等雨停”“你怎样理解这张长椅？”“长椅的意义改成一起看天亮”“清掉你对长椅的理解”。第一场雨也可以获得新的意义。原始创建或教学原话作为来源单独保留；清除注解不会倒改原来的对话，也不代表清空所有本机记录。删除物件会移除当前物件及其注解，主线片刻仍在。

提到多个可能的对象、指代已经不明确或没有说清要忘掉哪一项时，先澄清。你可以直接用物件名称继续聊，或在「世界」页查看它。离线版本只能生成可调整的简化字符轮廓，并理解一部分直接指令；它会说明限制，不把占位轮廓说成真实模型生成的复杂图案。

## 视觉边界

右侧世界仅用单一中性灰白色字符与黑底构成，明暗通过字符密度和透明度变化。对话、按钮、边框保持原来的青灰、象牙白与暖色 UI。RGB 输入或通过上传图片认识颜色，是未来章节方向，当前 demo 不提供上传或颜色教学。
